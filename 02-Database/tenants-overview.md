# ภาพรวมทุกร้าน (tenant) บน server ทดสอบ

กลับไป [[00-Index]] · โครงสร้าง database [[database-layout]] · server [[server-layout]] · ความหมายตัวเลือก [[company-options]]

> ผู้ใช้แจ้งว่าทุก database บน server นี้เป็นข้อมูล demo ไม่ใช่ production · ตัวเลขด้านล่างเป็น snapshot วันที่ 2026-10-21 (สร้างจาก `profile.sql` + query ตัวเลือก)

## 1. provider → data database (`sml_database_list` ใน `smlerpmain<provider>`)

| main database (provider) | data_code → database (data_group) | จำนวนผู้ใช้ใน `sml_user_list` |
|---|---|---|
| `smlerpmainaoy` (AOY) | AOY → aoy (SML) | 2 |
| `smlerpmaincus` (CUS) | THAO_AUTO → thao_auto (SML) | 5 |
| `smlerpmaincusms` (CUSMS) | CUS_MS → cus_ms (SML) | 9 |
| `smlerpmaindemo` (DEMO) | AKABEKO, DEBUG_KBGDS_DATA1, DEMO, DEMO2, KBGTEST, PLOY_TEST, SAMAI, WAWACRM (SML ทั้งหมด) | 11 |
| `smlerpmainkbyt` (KBYT) | KBYT → kbyt, KBYT_V → kbyt_v (SML) | 18 |
| `smlerpmainnext` (NEXT) | AOY → aoy, BEER, KUNG, PLOY (SML) | 1 |

ข้อเท็จจริงที่ได้:
- **data database เดียวลงทะเบียนได้หลาย provider** — `aoy` อยู่ทั้ง AOY และ NEXT; ผู้ใช้/สิทธิ์/session แยกกันตาม main database ที่ login (การทดสอบ AOY ทั้ง 3 รอบใช้ NEXT, ดู [[login-flow]])
- `data_database_name` เก็บเป็นตัวพิมพ์ใหญ่ (`AOY`) ส่วน database จริงชื่อตัวเล็ก (`aoy`) — PostgreSQL แปลงชื่อที่ไม่ใส่ `"` เป็นตัวเล็ก
- ทุก data database มีคู่ `<db>_images` และ `<db>_logs` · บน PostgreSQL ตัวนี้มี database ทั้งหมด 60 ตัว: main 6, `_images`/`_logs` 32, ที่เหลือเป็น data database + database ที่ไม่ใช่ของ SML (ไม่ได้สำรวจ)
- ผลต่อ sml_mcp_ai: tenant = **(provider, data_code)** ไม่ใช่แค่ชื่อ database; การตรวจสิทธิ์ผู้ใช้ต้องอ่านจาก main database ของ provider นั้น

ข้อเท็จจริงที่ได้ (ใช้ตัดสินใจออกแบบ sml_mcp_ai):
- **ไม่มีร้านไหนเปิด `gl_process_realtime`** → บนชุดข้อมูลนี้ GL เกิดจากการประมวลผล batch ทั้งหมด ([[pricing-vat-gl]]) — แต่ยังต้องอ่านค่าก่อนเขียนทุกครั้ง (ADR-001 ข้อ 4)
- `inventory_gl_post` ต่างกันระหว่างร้าน (1 = 9 ร้าน, 0 = cus_ms, akabeko, debug_kbgds_data1, wawacrm)
- `request_ar_credit` = 1 เฉพาะ `samai` → เฉพาะร้านนี้ที่การขายเกินวงเงินจะเข้า flow ขออนุมัติ (`ic_trans_draft` + OTP) ดู [[adr-001-write-path]]
- `thao_auto` ใช้หลายสกุลเงิน (`multi_currency`=1, `home_currency`=KIP), VAT 10% และทศนิยม 0 ทุกตัว → **API ห้าม hard-code VAT 7% และทศนิยม 2 ตำแหน่ง**
- ทศนิยมราคาต่างกันมาก (`item_price_decimal` 0–7, `item_amount_decimal` 0–5, `item_qty_decimal` 0–3) → การปัดเศษต้องอ่านจากร้าน
- `lock_credit_money`/`warning_credit_money` = 1 ใน demo, demo2, kbgtest, samai, wawacrm, kbyt → ต้องตรวจวงเงินลูกค้าก่อนบันทึกขายเชื่อ
- `stock_*_control`, `issue_stock_control`, `transfer_stock_control`, `ic_stock_control` ต่างกันทุกร้าน → การเช็กสต็อกติดลบ/ค้างจองต้องอ่านค่าก่อน
- `akabeko`: มีเอกสาร 24 ใบที่มี `sale_shift_id` แต่ `use_sale_shift` = 0 ตอนนี้ (ยังไม่ทราบว่าเคยเปิดแล้วปิด หรือมาจากช่องทางอื่น)
- `disable_ic_cost_process` และ `disable_auto_stock_process` = 0 ทุกร้าน → ทุกร้านคาดหวังให้ต้นทุนถูกคำนวณจากคิว ([[stock-cost]] § ใครเป็นคนหยิบคิว)

## 5. ข้อสังเกตเชิงข้อมูล
- `cus_ms`, `kbgtest` มี `max(doc_date)` = 2026-10-27 ซึ่งเลยวันที่สำรวจ (2026-10-21) — ข้อมูลมีเอกสารลงวันที่ล่วงหน้า; query ที่สรุปถึง "วันนี้" ต้องกรองวันที่เอง
- `kbgtest.process` ค้าง 10 แถว (`IC`, 3 ค่า wherein ไม่ซ้ำ) สร้าง 2026-10-16 ถึง 2026-10-19 ยังไม่ถูกหยิบ ([[stock-cost]])
- `kbyt` เหลือ `ic_trans` 2 ใบ (บันทึก 2026-10-20 ใน [[database-layout]] ว่ามี 16 ใบ — ข้อมูลถูกลบ/ล้างระหว่างนั้น ยังไม่ทราบสาเหตุ)
- ชุดใหญ่สำหรับทดสอบประสิทธิภาพ: `kbgtest` (17 GB, ic_trans 1.09M, 16 คลัง, 9 สาขา), `samai` (11 GB, POS 303k), `wawacrm` (8.8 GB, POS 254k, ใช้ 310/315)
- ชุดที่ใช้กะ (`sale_shift_id`): มีเฉพาะ `akabeko`
- ชุดที่ใช้ทุก cost_type 0–3: `kbgtest`, `kbyt`, `kbyt_v` (อย่างละไม่กี่สินค้า) — ใช้ทดสอบต้นทุน FIFO/FEFO ได้
