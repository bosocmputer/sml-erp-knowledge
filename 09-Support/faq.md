**วิธีอ่าน:** แต่ละข้อมี อาการ/ข้อความที่ร้านเห็น → สาเหตุ → วิธีแก้ → ผลต่อบัญชี/ภาษี → ระดับความเชื่อมั่น

- 🔶 **จากโค้ด** = อ่านจากโค้ดโปรแกรม ยังไม่ได้ทดสอบจริง — **ก่อนตอบร้าน ให้บอกว่า "ตามโครงสร้างโปรแกรม" และถ้าไม่ตรง ให้ส่งต่อทีม dev**

## A. ยกเลิกเอกสาร

### A1 ยกเลิกบิลขายไม่ได้
**ข้อความที่ร้านเห็น** (เมนู ขาย › รายงาน/ยกเลิก › ยกเลิกขายสินค้า/บริการ):
- "เอกสารนี้มีการยกเลิกไปแล้ว ไม่สามารถนำมายกเลิกได้" → บิลนี้**ถูกยกเลิกไปแล้ว**
- "เอกสารนี้มีปิดรายการไปแล้ว ไม่สามารถนำมายกเลิกได้" → บิลถูก**ปิดรายการ** (สิ้นสุดแล้ว)
- "เอกสารนี้มีการอ้างอิงรายการไปแล้ว ไม่สามารถนำมายกเลิกได้" → บิลถูก**เอกสารอื่นใช้ต่อแล้ว** เช่น รับชำระแล้ว (🔶 ตามโค้ด แม้จ่ายไม่ครบก็นับ), ทำใบวางบิลแล้ว, หรือทำใบลดหนี้/รับคืนอ้างบิลนี้แล้ว

**วิธีแก้:** หาเอกสารที่อ้างบิลนี้ แล้วยกเลิกเอกสารนั้นก่อน (ยกเลิกใบรับชำระ / ใบวางบิล / ใบลดหนี้) จากนั้นค่อยยกเลิกบิล
- 🔶 การที่ยกเลิกใบรับชำระ/ใบวางบิลแล้ว บิลกลับมายกเลิกได้ มาจากโค้ด (สถานะ "ถูกใช้" คำนวณใหม่จากเอกสารที่ยังไม่ถูกยกเลิก) ยังไม่ได้ทดสอบจริง

**ระดับ:** ✅ ข้อความและเงื่อนไขห้ามยกเลิก (โค้ด + ทดสอบรับชำระ/วางบิล/ลดหนี้ที่ทำให้สถานะเปลี่ยนจริง)
> สำหรับ dev: `_icTransScreenTopControl.cs` ~5491; `last_status`, `doc_success`, `used_status`, `used_status_2` — [[write-spec-cancel]] A.1, [[write-spec-receipt]] §3, [[write-spec-billing-note]] §3

### A2 ยกเลิกบิลแล้ว แต่ภาษีขาย GL ยังมีรายการ
**อาการ:** ยกเลิกบิลขายแล้ว แต่ในรายงานภาษีขายยังเห็นบิลนั้น หรือสมุดรายวัน (GL) ยังมีรายการของบิล
**สาเหตุ:**
- การยกเลิกใน SML = **สร้างใบยกเลิกขึ้นมาอีกใบ** บิลเดิมไม่ถูกลบ แค่ถูกทำเครื่องหมายว่ายกเลิก
- **รายงานภาษีขาย** ยังแสดงบิลที่ยกเลิก แต่ฐานภาษีและภาษีเป็น **0** — เป็นพฤติกรรมปกติ
- **GL:** การประมวลผล GL ยังลงบัญชีของบิลที่ยกเลิก และ**บัญชีจะถูกกลับรายการเฉพาะร้านที่ตั้งเล่มบัญชี (GL Book) ให้รูปแบบเอกสาร "ยกเลิกขาย"** แล้วประมวลผล GL ของเอกสารยกเลิกด้วย
**วิธีแก้:** ตรวจ เริ่มต้น › รายละเอียดข้อมูลทั่วไป › กำหนดรูปแบบเลขที่เอกสาร ของเอกสารยกเลิกขาย (เช่นรหัส SIC) ว่าตั้งเล่มบัญชีแล้วหรือยัง แล้วประมวลผล GL ใหม่
**ผลต่อบัญชี:** ถ้าไม่ได้ตั้ง บัญชีของบิลที่ยกเลิกจะค้างอยู่ (ยอดขายใน GL สูงเกินจริง)
**ระดับ:** ✅ แถวภาษี/GL ยังอยู่หลังยกเลิก (ทดสอบจริง + ข้อมูล 4 ร้าน) · 🔶 รายงานภาษีแสดงยอด 0 และวิธีแก้ GL (โค้ด + เทียบการตั้งค่าหลายร้าน)
> สำหรับ dev: GL batch กรอง `is_cancel=0` ไม่ใช่ `last_status`; ร้านที่ `erp_doc_format.gl_book` ของ 45 ว่างไม่มี GL กลับรายการ — [[write-spec-cancel]] A.4, [[tax-period]] §1

### A3 ยกเลิกใบสั่งขาย แล้วใบเสนอราคากลับมาใช้ได้
**อาการ:** ยกเลิกใบสั่งขาย (แบบยกเลิกทั้งหมด) แล้วใบเสนอราคาที่ดึงมากลับมาเป็นสถานะยังไม่ถูกใช้
**สาเหตุ:** ถูกต้องตามระบบ — เมื่อใบสั่งขายถูกยกเลิก ระบบคืนสถานะให้ใบเสนอราคาต้นทาง ดึงไปทำใบสั่งขายใหม่ได้
**ระดับ:** ✅ ทดสอบจริง
> สำหรับ dev: [[write-spec-cancel]] B.0

## B. ต้นทุน สต็อก

### B1 กำไร ต้นทุนไม่ขึ้น หรือต้นทุนเป็น 0
**อาการ:** บันทึกขาย/ซื้อแล้ว รายงานกำไรขั้นต้นหรือต้นทุนของบิลยังเป็น 0 หรือไม่เปลี่ยน
**สาเหตุ:** SML คำนวณต้นทุน**ภายหลัง**จากคิวงาน และ**คนที่หยิบคิวไปคำนวณคือโปรแกรม SML ที่เปิดอยู่บนเครื่องผู้ใช้** (เครื่องละ 3 งานย่อย ทุก 10 วินาที) — ถ้าไม่มีใครเปิดโปรแกรมของร้านนั้นอยู่เลย (เช่น บันทึกเอกสารจากระบบอื่นตอนกลางคืน) ต้นทุนจะค้าง
**วิธีแก้:** เปิดโปรแกรม SML ของร้านนั้นทิ้งไว้สักครู่ แล้วเปิดรายงานใหม่ (ตามปกติต้นทุนขึ้นภายในไม่กี่วินาทีหลังบันทึก — เห็นจากการทดสอบ)
**ผลต่อบัญชี:** กำไรในรายงานไม่ถูกต้องจนกว่าคิวจะถูกคำนวณ
**ระดับ:** ✅ ทดสอบจริง + โค้ด + ข้อมูล (มีร้านทดสอบที่คิวค้างหลายวันเพราะไม่มีคนเปิดโปรแกรม)
> สำหรับ dev: ตาราง `process` ('IC'), `SMLAccount/_mainForm.cs` thread "SML Thread 0..2" — [[stock-cost]] § ใครเป็นคนหยิบคิว

### B2 ขายไม่ได้ ขึ้นว่า ห้ามติดลบ
**ข้อความ:** "สินค้า : … ,คลัง : … ห้ามติดลบ" (หรือมี ที่เก็บ : … ด้วย)
**สาเหตุ:** ร้านเปิดตัวเลือก "ห้ามสต็อกติดลบ" และยอดคงเหลือของสินค้าในคลัง/ที่เก็บนั้นไม่พอ
**วิธีแก้:** ตรวจยอดคงเหลือของคลัง/ที่เก็บที่เลือกในบรรทัด — อาจเลือกคลังผิด หรือยังไม่ได้บันทึกรับสินค้า; ถ้าร้านต้องการให้ติดลบได้ ต้องปิดตัวเลือกใน เริ่มต้น › รายละเอียดข้อมูลทั่วไป › กำหนดข้อเลือกพิเศษต่างๆ (ตัดสินใจโดยร้าน)
**ระดับ:** 🔶 จากโค้ด (ข้อความและการตรวจ `_checkBalance`)
> สำหรับ dev: `SMLInventoryControl/_icTransItemGridControl.cs` ~12320; ตัวเลือก `issue_stock_control`, `stock_balance_control` — [[company-options]], [[tenants-overview]] §4

### B3 ยอดค้างส่ง ค้างจองไม่ลด
**อาการ:** ทำบิลจากใบสั่งขายแล้ว แต่ยอด "ค้างส่ง" ของสินค้าไม่ลด หรือยอดค้างจองค้าง
**สาเหตุที่ต้องตรวจ:**
- บิลต้อง**ดึงจากใบสั่งขาย** (ไม่ใช่พิมพ์รายการใหม่เอง) ยอดค้างส่งจึงจะถูกตัด
- ยอดค้างส่งคิดจาก จำนวนในใบสั่งขาย − จำนวนในบิลที่อ้างใบสั่งขาย − ยกเลิกรายสินค้า
- ระบบคำนวณยอดใหม่หลังบันทึก (หลังปิดหน้าพิมพ์) — ถ้าผู้ใช้ค้างหน้าพิมพ์ไว้ ยอดยังไม่เปลี่ยน
**ระดับ:** ✅ สูตรและลำดับเวลา (ทดสอบจริง)
> สำหรับ dev: CTE `accout`/`bookout` — [[stock-cost]], [[write-spec-sale-order]] §0, §3

## C. ลูกหนี้ เจ้าหนี้

### C1 ยอดลูกหนี้คงค้างไม่ตรงที่ร้านคิด
**สาเหตุที่พบบ่อย:**
- ยอดลูกหนี้ = บิลขายเชื่อ + เพิ่มหนี้ − ลดหนี้ − รับชำระ (เฉพาะเอกสารที่**ไม่ถูกยกเลิก**)
- **ใบวางบิลไม่ลดยอดลูกหนี้** — ลดเมื่อทำใบรับชำระเท่านั้น
- ใบลดหนี้ที่หักลูกหนี้คือ "รับคืนจากขายเงินเชื่อ" และ "ลดหนี้จากขายเงินเชื่อ" — แบบ "เงินสด" ไม่หักลูกหนี้ (คืนเงินแทน)
- เอกสารลงวันที่ล่วงหน้ายังถูกนับถ้าดูยอดถึงวันที่นั้น
**ระดับ:** ✅ สูตรจากคำสั่งจริงของโปรแกรม (หน้าจอรับชำระ/ตรวจวงเงิน) · 🔶 ประเภทใบลดหนี้แบบไม่กระทบสต็อก (ยังไม่ได้ทดสอบ)
> สำหรับ dev: [[write-spec-sale-invoice]] §1.3, [[write-spec-receipt]] §1, [[write-spec-credit-note]] §1

### C2 วางบิลแล้ว ยกเลิกบิลไม่ได้
**สาเหตุ:** ทำใบวางบิลแล้ว บิลถือว่า "ถูกอ้างอิง" เหมือนรับชำระแล้ว → ขึ้น "เอกสารนี้มีการอ้างอิงรายการไปแล้ว…" ดู [[#A1 ยกเลิกบิลขายไม่ได้]]
**วิธีแก้:** ยกเลิกใบวางบิลก่อน (🔶 ผลหลังยกเลิกใบวางบิลยังไม่ได้ทดสอบจริง)
**ระดับ:** ✅ สถานะหลังวางบิล (ทดสอบจริง)
> สำหรับ dev: `used_status_2` จาก 235/239 — [[write-spec-billing-note]]

### C3 เกินวงเงินเครดิตลูกค้า
**ข้อความ:** "เกินวงเงินเครดิตลูกค้า" / "ยอดวงเงินเครดิตของลุกค้า เกินที่กำหนดไว้"
**สาเหตุ:** ร้านเปิดการเตือน/ล็อกวงเงิน และยอดบิลนี้ + ยอดค้างเดิมเกินวงเงินในข้อมูลลูกค้า (ใบสั่งขายตรวจเฉพาะร้านที่เปิดการตรวจวงเงินของใบสั่งขาย)
**วิธีแก้:** ตรวจวงเงินในข้อมูลลูกค้า และยอดค้างตาม [[#C1 ยอดลูกหนี้คงค้างไม่ตรงที่ร้านคิด]]; ร้านที่ใช้ระบบขออนุมัติวงเงิน ให้ทำตามขั้นอนุมัติของร้าน
**ระดับ:** ✅ สูตรยอดค้างที่ใช้ตรวจ · 🔶 การตัดสินใจเตือน/ห้าม/ขออนุมัติ (ร้านทดสอบปิดตัวเลือกนี้ทั้งหมด)
> สำหรับ dev: `_creditMoneySaleCheck`, `sr_ss_credit_check`, `request_ar_credit` — [[write-spec-sale-invoice]] §1.3, [[write-spec-sale-order]] §1

## D. เลขที่ งวด วันที่

### D1 เลขที่เอกสารซ้ำ
**ข้อความ:** "เลขที่เอกสารซ้ำ" ตามด้วยข้อความ error ภาษาอังกฤษ (duplicate key …)
**สาเหตุ:** โปรแกรม**กำหนดเลขที่ตอนเปิดหน้าจอเอกสาร** (เลขล่าสุด + 1) ไม่ได้จองเลขไว้ — ถ้า 2 เครื่องเปิดเอกสารประเภทเดียวกันพร้อมกัน เครื่องที่บันทึกทีหลังจะได้เลขซ้ำ ระบบฐานข้อมูลจึงปฏิเสธทั้งเอกสาร (ไม่มีข้อมูลบันทึกครึ่ง ๆ กลาง ๆ)
**วิธีแก้:** ให้เครื่องที่ขึ้น error ขอเลขใหม่ (ล้างเลขที่/เปิดเอกสารใหม่) แล้วบันทึกอีกครั้ง
**ระดับ:** ✅ ทดสอบจริง (เวลาออกเลข) + โค้ด (ข้อความ)
> สำหรับ dev: unique `(doc_no, trans_flag)`; `_errorText` — [[write-spec-sale-order]] §1, [[error-messages]]

### D2 ขึ้นว่า ถูกปิดงวดไปแล้ว หรือยังไม่ได้กำหนดงวดบัญชี
**ข้อความ:** "คำเตือน! วันที่ปัจจุบัน หรือที่เอกสารที่กำหนด ได้ถูกปิดงวดไปแล้ว หรือยังไม่ได้กำหนดงวดบัญชี…" หรือ "ยังไม่ได้กำหนดงวดบัญชี แนะนำให้กำหนดก่อน"
**สาเหตุ:** วันที่เอกสารอยู่ในงวดที่ปิดแล้ว **หรือไม่อยู่ในงวดใดเลย** (เช่น ขึ้นปีใหม่แต่ยังไม่ได้สร้างงวดของปีนั้น)
**วิธีแก้:** เริ่มต้น › ระบบบัญชี › กำหนดงวดบัญชี — สร้างงวดของปีที่ยังไม่มี หรือ (ถ้าร้านตัดสินใจ) เปิดงวดที่ปิด
**ระดับ:** 🔶 จากโค้ด (ข้อความ + เงื่อนไข) + ข้อมูลงวดของร้านจริง
> สำหรับ dev: `_checkOpenPeriod` — [[tax-period]] §3

### D3 บันทึกขาย ซื้อย้อนไปในงวดที่ปิดแล้วได้
**อาการ:** ปิดงวดแล้ว แต่ยังบันทึกบิลขาย/ซื้อ/ใบสั่งขาย ลงวันที่ในงวดนั้นได้ (มีแค่คำเตือนตอนเปิดหน้าจอ) ขณะที่ใบรับชำระ/จ่ายชำระบันทึกไม่ได้
**สาเหตุ:** ตามโค้ด หน้าจอเอกสารสินค้า (ขาย/ซื้อ/สต็อก) **ไม่ได้ตรวจงวดตอนบันทึก** ตรวจเฉพาะตอนยกเลิกและลบ ส่วนหน้าจอลูกหนี้/เจ้าหนี้ตรวจตอนบันทึก
**วิธีแก้/คำแนะนำร้าน:** ใช้ตัวเลือก "ห้ามแก้ไขวันที่/เลขที่เอกสาร" ([[#D4 แก้วันที่ เลขที่เอกสารไม่ได้]]) กับผู้ใช้ที่ไม่ควรลงวันที่ย้อน; ตัวเลือก "ล็อกวันที่ย้อนหลัง" ในหน้าจอตัวเลือก **ไม่พบว่ามีผลในโค้ด**
**ผลต่อบัญชี:** เอกสารย้อนงวดเปลี่ยนตัวเลขของงวดที่ปิดแล้ว
**ระดับ:** 🔶 จากโค้ด (ค้นทั้ง codebase) — ยังไม่ได้ทดสอบจริง
> สำหรับ dev: [[tax-period]] §3–4

### D4 แก้วันที่ เลขที่เอกสารไม่ได้
**อาการ:** ช่องวันที่ เวลา และเลขที่เอกสารกดแก้ไม่ได้ วันที่เป็นวันนี้เสมอ
**สาเหตุ:** ร้านเปิดตัวเลือก "ห้ามแก้ไขเลขที่และวันที่เอกสาร" ทั้งร้าน หรือเปิดให้**ผู้ใช้คนนั้น** (ในข้อมูลผู้ใช้)
**วิธีแก้:** ผู้ดูแลของร้านตรวจตัวเลือกของร้าน และข้อมูลผู้ใช้คนนั้น
**ระดับ:** 🔶 จากโค้ด + ข้อมูลจริง (หลายร้านเปิดรายผู้ใช้)
> สำหรับ dev: `erp_option.disable_edit_doc_no_doc_date`, `erp_user.disable_edit_doc_no_doc_date_user` — [[tax-period]] §4

## E. สิทธิ์ การใช้งานพร้อมกัน

### E1 ท่านไม่มีสิทธิในการเพิ่มข้อมูลใหม่
**สาเหตุ:** ผู้ใช้ (หรือกลุ่มที่ผู้ใช้อยู่) ไม่มีสิทธิ์ "เพิ่ม" ของเมนูนั้น — สิทธิ์ของผู้ใช้กับของกลุ่มรวมกันแบบ "อย่างใดอย่างหนึ่งมีสิทธิ์ก็ได้"
**วิธีแก้:** ผู้ดูแลระดับ Admin/Super Admin เข้าแผงผู้ดูแลตอน login แล้วกำหนดสิทธิ์เมนูนั้นให้ผู้ใช้หรือกลุ่ม
**ระดับ:** 🔶 จากโค้ด + ข้อมูลสิทธิ์จริง
> สำหรับ dev: `warning19`/`warning44`, `sml_permissions_user/_group` — [[permissions]]

### E2 ไม่อนุญาติให้แก้ไขข้อมูล
**ข้อความ:** "ไม่อนุญาติให้แก้ไขข้อมูล" (ตอนบันทึกข้อมูลหลัก เช่น สินค้า) หรือ "หน้าจอนี้ไม่อนุญาติให้แก้ไขข้อมูล"
**สาเหตุ:** กลุ่มผู้ใช้ไม่ได้รับสิทธิ์ "แก้ไขข้อมูลหลัก" หรือหน้าจอนั้นเปิดแบบอ่านอย่างเดียว
**วิธีแก้:** ผู้ดูแลตรวจกลุ่มผู้ใช้ในข้อมูลของร้าน (สิทธิ์แก้ไขข้อมูลหลัก)
**ระดับ:** 🔶 จากโค้ด
> สำหรับ dev: `erp_user_group.is_change_masterdata` → `_allowChangeMaster` — [[permissions]] §3

### E3 รายการนี้มีผู้ใช้อยู่
**สาเหตุ:** มีอีกเครื่อง**เปิดเอกสาร/ข้อมูลนี้เพื่อแก้ไขอยู่** ระบบจึงล็อกไว้ไม่ให้แก้พร้อมกัน
**วิธีแก้:** ให้เครื่องที่เปิดอยู่ปิดหน้าจอนั้น — ถ้าเครื่องนั้นโปรแกรมค้างหรือปิดไม่ปกติ ล็อกจะถูกปลดเมื่อ**ทุกคน logout** หรือเมื่อ session ของเครื่องนั้นหมดอายุแล้วมีคน logout (ระบบปลดล็อกที่ไม่มี session แล้วตอน logout)
**ระดับ:** ✅ กลไกล็อก/ปลดล็อก (ทดสอบจริง) · 🔶 ข้อความ (โค้ด)
> สำหรับ dev: `guid_code`, `warning52`, `_unlockRecord` — [[document-engine]] § การล็อกเอกสาร

### E4 เข้าหน้าจอ Admin ไม่ได้
**ข้อความ:** "ท่านไม่ใช่กลุ่ม Admin ไม่อนุญาติให้ Login ในหน้าจอ Admin"
**สาเหตุ:** ระดับผู้ใช้เป็น User หรือ Super User — แผงผู้ดูแลเข้าได้เฉพาะ Admin และ Super Admin
**ระดับ:** 🔶 จากโค้ด
> สำหรับ dev: `user_level` 0–3, `warning92` — [[permissions]] §1

### E5 ใช้ไปสักพักแล้วหลุด ต้อง login ใหม่
**สาเหตุที่ต้องตรวจ:** โปรแกรมแจ้ง server ทุกประมาณ 60 วินาทีว่ายังใช้อยู่ ถ้า server ไม่ได้รับเกิน **5 นาที** (เน็ตหลุด, เครื่องหลับ, โปรแกรมค้าง) session จะหมดอายุ
**วิธีแก้:** ตรวจการเชื่อมต่อเครือข่ายของเครื่องลูกกับ server และการตั้งค่าพักเครื่อง
**ระดับ:** ✅ ทดสอบจริง (รอบเวลา) + โค้ด (5 นาที)
> สำหรับ dev: `_sendGuid`, `sml_guid` — [[login-flow]]

## F. สินค้า

### F1 บันทึกสินค้าใหม่ไม่ได้
**ข้อความและสาเหตุ:**
- "ไม่พบหน่วยต้นทุนในตารางหน่วยนับ" / "ไม่พบหน่วยมาตรฐานในตารางหน่วยนับ" → หน่วยต้นทุน/หน่วยมาตรฐานที่เลือก ต้องมีอยู่ในตารางหน่วยนับของสินค้านั้นด้วย
- "ยังไม่บันทึกคลังที่เก็บ" → ต้องใส่คลัง/ที่เก็บอย่างน้อย 1 แถว (ยกเว้นร้านที่เปิดตัวเลือกให้ใช้ทุกคลัง)
- ช่องที่ห้ามว่าง: รหัสสินค้า, ชื่อ, หน่วยต้นทุน, หน่วยมาตรฐาน
**ระดับ:** ✅ การสร้างสินค้า (ทดสอบจริง) · 🔶 เงื่อนไขข้อความ (โค้ด)
> สำหรับ dev: [[write-spec-master-product]] §3, §10

### F2 ลบสินค้าไม่ได้
**ข้อความ:** "สินค้ามีการใช้ไปแล้ว ห้ามลบ : <รหัส>"
**สาเหตุ:** สินค้านี้มีในเอกสารแล้วอย่างน้อย 1 ใบ — SML ไม่ให้ลบเพื่อไม่ให้ประวัติเสีย
**วิธีแก้:** ไม่ลบ — ให้ปิดการใช้งาน/ระงับการซื้อขายแทน (ตามที่ร้านใช้)
**ระดับ:** 🔶 จากโค้ด
> สำหรับ dev: `_icMain._dataList__deleteData` — [[write-spec-master-product]] §7

### F3 บาร์โค้ด รหัสซ้ำ
**ข้อความ:** "รหัสซ้ำ" ตามด้วย error ภาษาอังกฤษ ตอนบันทึกสินค้า/บาร์โค้ด
**สาเหตุ:** **บาร์โค้ดหนึ่งตัวใช้ได้กับสินค้าเดียวทั้งร้าน** — บาร์โค้ดนี้มีอยู่แล้วในสินค้าอื่น
**วิธีแก้:** ค้นบาร์โค้ดนั้นในเมนู ข้อมูลสินค้า (แสดงตามบาร์โค้ด) แล้วเอาออกจากสินค้าเดิม หรือใช้บาร์โค้ดใหม่
**ระดับ:** ✅ ข้อจำกัดของฐานข้อมูล (ตรวจจริงทุกร้าน) · 🔶 ข้อความ (โค้ด)
> สำหรับ dev: unique `ic_inventory_barcode.barcode` — [[write-spec-master-product]] §1

## G. แก้ไขเอกสาร

### G1 แก้ใบสั่งขายแล้ว สถานะใบเสนอราคาเปลี่ยน
**อาการ:** ใบเสนอราคาที่ดึงไปครบแล้ว กลับมาเป็น "ยังไม่สิ้นสุด" หลังแก้ใบสั่งขาย
**สาเหตุ:** ถูกต้องตามระบบ — ถ้าแก้จำนวนในใบสั่งขายให้น้อยกว่าใบเสนอราคา ใบเสนอราคายังเหลือจำนวนที่ดึงต่อได้
**ระดับ:** ✅ ทดสอบจริง
> สำหรับ dev: การแก้ไข = ลบแล้วใส่ใหม่ (`roworder` เปลี่ยน) — [[write-spec-sale-order]] §6.2
